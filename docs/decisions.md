# سجل القرارات

التاريخ: 2026-10-16 · المرحلة: 1 فقط · المرجع التفصيلي: [المواصفة](project-spec.md).

## مؤكد بتعليمات المستخدم

| ID | القرار |
| --- | --- |
| U01 | الاسم الكامل حرفيًا على جميع الصفحات، عربية فصحى وRTL، هوية أكاديمية، هاتف ولابتوب، placeholders واضحة عند غياب الأسماء والشعارات. |
| U02 | الترتيب النهائي: خلفية نظرية → Google Forms → Teams → Mendeley. دروس الموديول الأول الثلاثة وعناصر الدرس الأول الخمسة كما في المواصفة. لا تقويم قبلي للدرس ولا امتحان بين الموديولات. |
| U03 | لا محتوى قبل تسليم القبلي؛ `<=50%` مؤهل، `>50%` غير مؤهل، مع الرسائل المحددة. الذاتي `>=50%` اجتياز. المقارنة قبل التقريب. |
| U04 | العناصر بالتسلسل ثم نشاط مكتمل الإجابات ومُسلّم بلا عتبة نجاح ثم ذاتي. اجتياز الذاتي يكمل الدرس، وكل دروس الموديول تفتح التالي، وآخر درس يفتح البعدي. |
| U05 | لا حد مخطط لإعادة الذاتي، ومحاولات متعددة دون وقت للقبلي والبعدي. النجاح لا يلغى بإعادة أقل، والنقاط والشارات مرة لكل حدث إكمال. |
| U06 | محتوى وأسئلة قابلة للتغيير بالبيانات ومعرفات ثابتة ونسخ وحالة اعتماد ومصادر. لا اختراع أدوار أو اعتماد الباحث. |
| U07 | المرحلة الحالية مواصفة فقط. لا Backend/DB في المراحل 1–4، ولا انتقال تلقائي للمرحلة الثانية. |
| U08 | `first-submitted-pre` خيار مؤقت للـdemo وحده؛ يسجل ما بعده دون تغيير الأهلية. لا يتحول إلى سياسة إنتاج بلا اعتماد صريح. |

## اختيارات تصميم مقترحة للتنفيذ لاحقًا

| ID | الاختيار والسبب |
| --- | --- |
| D01 | المشروع بلا تطبيق أو حزم؛ نعتمد خطة React/TypeScript strict/Vite/React Router، وTailwind tokens، وفق اقتراح المستخدم. تحدد الإصدارات المستقرة المتوافقة من التوثيق الرسمي عند الإعداد ويضاف lockfile حينها، لا إصدارات متخيلة الآن. |
| D02 | router واحد بموديولات/دروس/عناصر معرفاتها ثابتة؛ أهداف عامة مستقلة عن محتوى الموديول المقفل. عقود في `contracts.ts` دون تنفيذ أو framework عام. |
| D03 | المثال الأولي للقبلي 20 مفردة = 15 اختيارًا متعدد البدائل باختيار واحد + 5 صح/خطأ بأوزان متساوية؛ اختلاف أسئلة القبلي والبعدي مبدئي. العدد والتركيب والوزن ليست اعتمادًا بحثيًا. |
| D04 | إجابة الجميع شرط التسليم في demo، والمراجعة والتأكيد منفصلان. القبلي/البعدي نسبة فقط دون تصحيح تفصيلي؛ النشاط والذاتي تغذية تعليمية بعد التسليم. |
| D05 | اقتراح النقاط: 10 لإكمال درس و50 لإكمال موديول، والمستوى عدد الموديولات المكتملة 0–4، والتقدم نسبة الدروس المكتملة. قابلة للتعديل؛ لا نقاط للقبلي/السرعة ولا منافسة عامة. |
| D06 | حفظ demo المقترح في المتصفح والجهاز نفسيهما مع إظهار الفشل، دون كلمات مرور حقيقية أو وعد بمزامنة/حفظ اتصال. تثبيت نسخة المحتوى أثناء المسار، والترحيل لاحقًا بسياسة معتمدة. لم ينفذ adapter أو حفظ الآن. |
| D07 | تقسيم شاشة الدرس بنقطة كسر أولية 1024px، والألوان والأزمنة والأحجام وفق المواصفة مع قياس التباين في التنفيذ. لا فحص بصري مزعوم في مرحلة الوثائق. |
| D08 | لا تركيب حزم تطبيق ولا نشر موقع: الطلب المحدد يقتصر على التخطيط والعقود؛ يسمح بأداة تحقق مؤقتة خارج المشروع. تبقى `.gitignore` كما هي ويضاف AGENTS مختصر يحمي القيود. |

`DEMO_STUDY_POLICY` في `contracts.ts` يعلن `scope: 'demo-only'` و`preEligibilityAttempt: 'first-submitted-pre'`، مع البعدي والشهادة صراحة غير محسومين. هذا config توثيقي لا خدمة تعمل. اعتماد أي سياسة إنتاج يتطلب تحديثًا صريحًا للقرارات والعقد قبل تنفيذه.

## قرارات بحثية معلقة — لا موافقة مفترضة

| ID | المطلوب من الباحث قبل التطبيق الفعلي للدراسة | السلوك المؤقت في العرض |
| --- | --- | --- |
| R01 | أي محاولة قبلي تحدد الأهلية عند الإعادة؟ | أول قبلي مُسلّم فقط؛ الباقي محفوظ مستقلًا. |
| R02 | أي محاولة بعدي تدخل التحليل؟ | حفظ جميع المحاولات دون وسم إحداها «المعتمدة للتحليل». |
| R03 | هل توجد عتبة للبعدي أو شهادة وشروطها؟ | نتيجة نسبة فقط؛ لا حكم اجتياز ولا شهادة. |
| R04 | هل يسمح بالتصحيح التفصيلي للبعدي، ومتى؟ | محجوب؛ لا إرسال مفاتيح في DTO الإنتاج. |
| R05 | اعتماد المحتوى والأسئلة والأهداف وأوزانها وأعداد/عناوين دروس الموديولات 2–4 وسياسة إجابة الكل. | draft موسوم في بيانات التحرير؛ لا اختلاق محتوى معتمد. |
| R06 | اعتماد نظام المحفزات والأسماء والنقاط والمستويات، والأسماء والأدوار والشعارات ووسائل الاتصال الفعلية. | بدائل واضحة ومقترحات قابلة للتهيئة؛ لا شعار رسمي مولد أو منصب مخمن. |

هذه القرارات لا تعطل توثيق المرحلة الأولى ولا تستلزم سؤالًا الآن. لا نفترض أن شرط الذاتي ينطبق على البعدي، ولا أن placeholder يمنح إذنًا بجمع بيانات حقيقية.
