## 2. الهوية والجمهور والتقنيات

الاسم المعتمد حرفيًا، في **كل صفحة** بما فيها الدخول والتسجيل والاستعادة والتقويم و404 وحالات الخطأ:

> بيئة تدريبية قائمة على محفزات الألعاب الرقمية لتنمية بعض مهارات دمج التكنولوجيا في التعليم لدى أعضاء الهيئة المعاونة بالكلية

بيئة للجانب التطبيقي لرسالة ماجستير بكلية التربية النوعية، جامعة الزقازيق. الجمهور أعضاء الهيئة المعاونة؛ عرض الباحث على لابتوب والاستخدام الفعلي متوقع بكثافة من الهاتف. لغة المنتج عربية فصحى بطابع أكاديمي للكبار، دون تفاصيل المطور في رحلة المتدرب.

المنفذ في المرحلة الثانية: React + TypeScript بوضع `strict` + Vite + React Router declarative. Tailwind CSS 4 مع Vite plugin وtokens وCSS logical properties؛ Lucide React للأيقونات. روجعت وثائق الإعداد الرسمية وتوافق الحزم قبل التثبيت؛ القيم الدقيقة في `package.json` و`package-lock.json`، وقرار التوافق في D10. لا تخلط APIs أو تعليمات major مختلف، خاصة Tailwind وReact Router.

CSS للتفاعلات الصغيرة؛ Motion من حزمة `motion` فقط إن احتاجت الانتقالات له، بعد التحقق من API الإصدار. أضيف React Hook Form + Zod للنماذج والتحقق من الحالة في الثالثة؛ reducer/context مستقلان لقواعد المحاكاة، وZustand بتبرير فقط. TanStack Query عند ربط API إذا أفاد. Radix أو shadcn/ui انتقائيًا للقوائم/الحوارات الميسرة، دون مكتبتين للغرض نفسه. Vitest/Testing Library للقواعد والمكونات المهمة وPlaywright للرحلات عند توفر مسار QA معتمد. لا اختبارات شكلية لكل CSS.

Backend لاحقًا من المرحلة الخامسة: ASP.NET Core على .NET LTS المدعوم وقت التنفيذ، EF Core متوافق، SQL Server، ASP.NET Core Identity. لا Backend أو DB في المراحل 1–4. لا حاجة افتراضية لـNext.js أو SSR أو Three.js/WebGL أو GSAP أو مكتبة carousel، ولا إنشاء CMS أو framework عام.

## 3. القالب المشترك والـresponsive

### 3.1 البنية الثابتة

- الوثيقة `lang="ar" dir="rtl"`. الأسماء التقنية والبريد تستخدم اتجاه LTR/`bdi` محليًا دون قلب الصفحة.
- رابط تجاوز إلى المحتوى، `header` ثم `nav` ثم `main` واحد، وعناوين هرمية. تذييل مختصر للهوية ووسائل الاتصال عند الحاجة.
- هيدر sticky في document flow: موضع شعار الجامعة يمينًا، الاسم الكامل وسطًا ويلتف على سطرين أو أكثر، وموضع شعار الكلية/القسم يسارًا. عند غياب الأصول تستخدم بدائل نصية موسومة «موضع شعار جامعة الزقازيق» و«موضع شعار الكلية/القسم»؛ لا توليد لشعار رسمي مزيف.
- في التنفيذ الحالي يكون الهيدر في التدفق الطبيعي على الهاتف لتوفير مساحة قراءة، دون إخفاء الاسم؛ ووسائل تنقل العنصر في نهاية المحتوى دون overlay.
- الروابط من اليمين: **الرئيسية، أهداف البيئة، دليل المتدرب، التقويم، المحتوى التعليمي، اتصل بنا**. الحالية مميزة نصيًا وبـ`aria-current` مع علامة مرئية، لا اللون وحده.
- «التقويم» قائمة قبلي/بعدي تعمل بالنقر واللمس والكيبورد. hover إضافة لأجهزة المؤشر الدقيق فقط. توضح إتاحة البعدي وسبب قفله حتى قبل الانتقال.
- Escape يغلق القوائم والحوارات ويعيد focus إلى مشغلها؛ الحوار/drawer يحصر focus خلال فتحه، مع عنوان وزر إغلاق واضحين. القائمة المنسدلة تتبع نمط تنقل ميسرًا متسقًا دون ARIA متناقضة.
- على الهاتف تصغر الشعارات والمسافات، **لا الاسم** ولا يُقص أو يُستبدل بـellipsis. تجمع الروابط في قائمة مسماة «قائمة التنقل الرئيسية». يغلق التنقل القائمة بعد اختيار وجهة.
- بيانات التحرير والاعتماد وأسباب السياسات المؤقتة مكانها التوثيق؛ لا تسرب أسماء adapters أو config أو مفاتيح التصحيح إلى تجربة المتدرب.

### 3.2 التصميم والحركة

- هوية أكاديمية حديثة دافئة: بترولي `#0B3C5D`، Cyan `#0891B2` وخلفية `#F3F8FC` كأساس قابل للضبط. يجب قياس تباين AA للنصوص والأزرار عند التنفيذ؛ لا تفترض صلاحية النص الأبيض فوق Cyan. يختار token أغمق للأزرار إن لزم.
- Cairo أو خط عربي واضح مرخص؛ يفضّل self-hosted مع ملف الترخيص عند توفره. متن الهاتف نحو 16–18px وتباعد أسطر مريح. النصوص حقيقية قابلة للتحديد، لا تُحشر داخل صور.
- بطاقات بحواف مستديرة وظلال خفيفة، عمق محدود ورسوم SVG صغيرة شبه ثلاثية الأبعاد للموديولات والشارات. لا صور شخصية لبطاقات الفريق ولا screenshots بواجهة متصفح كأصول نهائية.
- رفع البطاقة 2–4px مع ظل/لون وخط تنقل متحرك لمدة 150–250ms؛ tilt بحد أقصى نحو 2° وعلى أجهزة hover فقط، مع بقاء النص مقروءًا. fade وإزاحة 6–10px للمحتوى لمدة 200–300ms.
- احتفال واحد قصير نحو ثانية عند إنجاز جديد فقط؛ يتوقف مع `prefers-reduced-motion`. لا bounce دائم أو parallax أو حركة متواصلة أثناء القراءة/الاختبارات، ولا صوت تلقائي.
- أهداف لمس مفضلة 44×44 CSS px أو أكبر، focus واضح، labels للنماذج وتسميات عربية للأزرار ذات الأيقونات وalt مناسب. النجاح والقفل لهما نص/رمز واضح، ولا معلومة أساسية داخل tooltip فقط.

### 3.3 القراءة والأحجام

- الشاشات الأساسية تعرض المهمة سريعًا؛ المحتوى الطويل يقسم إلى أجزاء تعليمية بأزرار «السابق/التالي» ومؤشر «الجزء 2 من 5». لا شرائح تلقائية ولا سحب إصبع كوسيلة وحيدة.
- لابتوب: sidebar الدرس/الموديول يمينًا والمحتوى بجواره. هاتف: زر «أقسام الدرس» يفتح drawer ميسرًا، مع القسم الحالي وتنقل سفلي لا يغطي النص. نقطة كسر أولية 1024px قابلة للتعديل بحسب المحتوى، وليست قيدًا بحثيًا.
- لا `overflow:hidden` على body لحبس المحتوى ولا ارتفاعات تقص النص ولا scale/zoom لتصغير الصفحة ولا تمرير أفقي للنص. يفضل تدفق واحد بتمرير رأسي دون scroll متداخل. يُسمح بقفل خلفية الحوار مؤقتًا فقط مع استعادة موضعها عند الإغلاق.
- `min-height` مرن و`100dvh` بحذر، مع حجز مساحة أي شريط sticky سفلي و`safe-area-inset-bottom`. يختبر تغير ارتفاع المتصفح ولوحة المفاتيح والنصوص الأطول. عند 320px أو تكبير 200% يظل الاسم والنص كاملين ولو زاد التمرير الرأسي.

| `/modules/:moduleId/lessons/:lessonId/self-assessment/attempt/:attemptId/:stage` | `review`، `confirm`، `result` |
| `*` | 404، بما فيه section/stage غير المعروف أو علاقة ID غير صحيحة |

المسارات الأكثر تحديدًا لا تُبتلع في `:section`. لا صفحة باحث إدارية في هذه المرحلة؛ صلاحياته المستقبلية موثقة فقط. لا روابط `#` أو أزرار بلا فعل. الرابط إلى مورد مقفل يعرض سببًا وخطوة متاحة بدل كشف النص. أهداف الموديول العامة تستعمل `/goals/:moduleId` حتى عند قفل `/modules/:moduleId/objectives`.

### 5.1 التنقل والحراسة

- التحقق بالترتيب: وجود المورد، توافق module/lesson/element، سياق المستخدم/ملكيته للمحاولة، ثم شرط الفتح. محاولة شخص آخر لا تكشف أسئلتها أو نتيجتها؛ الإنتاج يرفضها من السيرفر. لا يكفي إخفاء رابط.
- نتيجة draft لا تعرض نتيجة؛ تعيد إلى المحاولة/المراجعة. محاولة مسلّمة عند فتح صفحة الأسئلة تعرض حالة القراءة فقط ورابط نتيجتها؛ لا تغيير لها. التأكيد لا يرسل تلقائيًا، والتحديث لا يعيد التسليم أو المكافأة.
- back/forward وrefresh والرابط المباشر يعيدان المورد/السؤال الصحيح؛ الحراسة تعاد بعد استرجاع الحالة. لا وميض لمحتوى مقفل خلال التحميل. query غير صالح يعاد لأول سؤال/جزء متاح؛ عنصر غير متاح يبقى مقفلًا.
- عند وجود draft صالح لنفس التعريف والنسخة يعرض «استكمال المحاولة»؛ إنشاء محاولة جديدة فعل صريح. المغادرة لا تُحتسب تسليمًا. خطأ الحفظ/الإرسال يبقي الإجابات ويتيح إعادة المحاولة دون مضاعفة سجل التسليم.

## 6. الحقائق المخزنة والحالات المشتقة

الحقائق: محتوى مرتب ونسخه، أول قبلي مُسلّم محدد، محاولات مستقلة، إقرارات إكمال العناصر، أول اجتياز ذاتي، وسجل المكافآت. حالات الأقفال والنسبة والمستوى تُشتق منها؛ لا مصدران متعارضان للحالة. يعاد حساب الاشتقاق في demo من snapshot المستعاد، ثم يصبح السيرفر مصدر الحقيقة في الإنتاج. التصميم في `contracts.ts` يميز حقائق `Progress` عن `ProgressSnapshot` المشتق.

### 6.1 eligibility

| الحالة | المصدر / الانتقال |
| --- | --- |
| `not-assessed` | لا محاولة قبلي مسلّمة محددة. draft أو مجرد زيارة القبلي لا يغيرها. |
| `eligible` | أول قبلي مُسلّم حسب إعداد العرض `first-submitted-pre`، ودرجته الدقيقة ≤50%. |
| `ineligible` | المحاولة المحددة نفسها ودرجتها الدقيقة >50%. |

النتيجة المرسلة تثبت في سجل المحاولة. «الأول» ترتيب التسليم الناجح لا إنشاء المسودة، ويرتبط بـ`attemptId` مرة واحدة؛ يتولى السيرفر الحسم الذري مستقبلًا. لا اعتماد لساعة الجهاز في الإنتاج. الإعادات تسجل ولا تغير الأهلية في demo. لا عقاب ولا نقاط على نتيجة القبلي، ولا تشجيع لتخفيضها.

الرسائل المعتمدة:

- مؤهل: «عزيزي المتدرب، لم تتجاوز نسبتك 50%، لذا يمكنك البدء بدراسة المحتوى التدريبي».
- غير مؤهل: «وفقًا لشروط المشاركة المحددة لهذه الدراسة، لا يتاح لك المسار التدريبي»، مع النسبة؛ لا تعميم بأنه لا يحتاج تعلمًا.

### 6.2 حالات المسار وانتقالاته

| الكيان والحالات | قاعدة الاشتقاق / الحدث المؤثر |
| --- | --- |
| Module: `locked / available / in-progress / completed` | مقفل إذا غابت الأهلية أو لم يكتمل السابق. الأول متاح للمؤهل. الثاني وما بعده عند إكمال كل دروس السابق. in-progress بعد بدء قراءة/محاولة داخل الموديول المتاح، completed عند اجتياز ذاتي كل دروسه، شرط أن يحتوي دروسًا فعلية. |
| Lesson: `locked / available / in-progress / completed` | يحتاج موديولًا متاحًا واجتياز الدرس السابق. أول درس يفتح مع الموديول. البدء يغير حالة التفاعل فقط؛ الإكمال بأول ذاتي ناجح، لا بالزيارة أو تسليم النشاط وحده. |
| Element: `locked / available / in-progress / completed` | يحتاج درسًا متاحًا وإكمال العنصر السابق. الأول متاح أولًا. فتحه/أجزائه لا يكمله. «تم الاطلاع — التالي» في نهاية آخر جزء يسجل إقرارًا واحدًا ويتيح التالي؛ يمكن الرجوع لكل مكتمل. الإقرار يثبت المرور والإقرار بالاطلاع فقط، لا الفهم أو الدراسة يقينًا. |
| Activity: `locked / available / in-progress / submitted` | يفتح بعد جميع العناصر الفعلية. أسئلة اختيار واحد؛ يجب إجابة الكل والتسليم. لا حد نجاح ولا أثر لدرجته في الفتح. تسليمه يفتح الذاتي مهما كانت النسبة. |
| Self: `locked / available / retry-available / passed` | مقفل قبل نشاط مسلّم مكتمل الإجابات. أقل من 50% يتيح المراجعة والإعادة دون حد مخطط؛ 50% فأكثر يسجل أول اجتياز ويكمل الدرس. اجتياز محفوظ يبقى passed مع محاولة لاحقة أقل. |
| Attempt: `draft / submitted` | draft يشمل الإجابة والمراجعة والتأكيد (هذه أوضاع UI، لا ثلاث حالات مجال إضافية). `saveAnswers` لا يسلم. `submit` يتحقق من إجابة جميع أسئلة النسخة، يثبت الإجابات والنتيجة ووقت التسليم. بعده لا تعديل؛ الإعادة Attempt جديد بمعرف مستقل. |
| المسار: `not-started / in-progress / training-completed / post-submitted` | من أهلية المتدرب وحقائق البدء وإكمال الموديولات. اكتمال جميع الدروس الفعلية في الموديولات الأربعة يفتح البعدي. submitted بعد محاولة بعدي واحدة على الأقل؛ لا يعني شهادة أو عتبة اجتياز بحثية. |

`in-progress` وصف للتفاعل، لا دليل تعلم ولا شرط نقاط. `review-needed` تفسير نتيجة ذاتي منخفضة لا يلغي إنجازًا سابقًا. الأقفال لها سبب ثابت قابل للترجمة: `account-required`، `pre-required`، `study-ineligible`، `previous-module-required`، `previous-lesson-required`، `previous-element-required`، `elements-required`، `activity-required`، `training-required`، `content-unavailable`، `attempt-not-submitted`، `not-owner`.

القسمان مقدمة/أهداف وقائمة العناصر متاحون داخل الدرس المفتوح؛ عنوان كل عنصر وحالة قفله واضحان، لكن نص العنصر المقفل لا يُكشف. لا إكمال وهمي بسبب قائمة فارغة (`every([])`): غياب عناصر/أسئلة/دروس مطلوبة يعرض «المحتوى غير متاح حاليًا» ويمنع الإكمال إلى حين توفر بيانات صالحة. لا يفرض مؤقت قراءة مصطنع.

### 6.3 الحساب والحدود

كل درجة ناتج `earned / possible` بأوزان موجبة؛ المجموع الصفري أو غير الصالح خطأ بيانات وليس 0% مؤهلًا. في نموذج العرض أوزان صحيحة متساوية، والإجابة الصحيحة تمنح وزن السؤال كاملًا. تغييرات الوزن مستقبلًا تُحفظ في نسخة تعريف جديدة. الشروط تقارن قبل تقريب النسبة، مثل `2 * earned <= possible` للقبلي و`2 * earned >= possible` للذاتي؛ التقريب للعرض فقط.

| المثال | أهلية القبلي | اجتياز الذاتي |
| --- | --- | --- |
| 0/20 = 0% | مؤهل | غير مجتاز |
| 9/20 = 45% | مؤهل | غير مجتاز |
| 10/20 = 50% | **مؤهل** | **مجتاز** |
| 11/20 = 55% | غير مؤهل | مجتاز |
| 20/20 = 100% | غير مؤهل | مجتاز |
| 5000/10001 ≈49.995% | مؤهل | غير مجتاز ولو عُرضت 50% |
| 5001/10001 ≈50.005% | غير مؤهل ولو عُرضت 50% | مجتاز |

عند تقارب الدرجة من الحد يزاد وضوح العرض بذكر الكسر/دقة إضافية، فلا تبدو الرسالة متناقضة مع نسبة مقربة. البعدي له نسبة فقط حاليًا؛ عتبة الذاتي لا تنتقل إليه.

### 6.4 الحفظ والنسخ

- لكل محاولة `assessmentVersion` و`contentVersion` وقائمة أسئلة/ترتيب ثابتة عند الإنشاء. إجاباتها مرتبطة بـquestionId لا برقم الشاشة. لا تبديل سؤال في draft بسبب تعديل بنك المحتوى.
- لكل إقرار إكمال ومكافأة نسخة مرجعية. الـdemo يثبت نسخة المحتوى أثناء المسار ولا يخلط تقدم نسختين؛ ترحيل تقدم الدراسة/الإصدارات قرار لاحق، ولا يمحو النجاح تلقائيًا.
- نُفذ حفظ drafts والتقدم بعد الإجابة والتنقل والإقرار والتسليم في المتصفح والجهاز نفسيهما، تحت `edu-training-demo:v1` مع `schemaVersion: 1` و`contentVersion`. الكتابة تسبق إعلان النجاح، والفشل يبقي الحالة السابقة. لا حساب مشترك عبر الأجهزة ولا مزامنة أو ضمان لاستمرار بيانات المتصفح؛ محوها يفقد المحاكاة، والتخزين ليس آمنًا.
- فشل القراءة أو فساد snapshot لا يتحول سرًا إلى متدرب جديد أو حالة مؤهلة؛ يقدم رسالة وخيار إعادة المحاولة/إعادة ضبط صريح يحذر من فقد البيانات المحلية. لا إعادة ضبط تلقائية.
- في الإنتاج يفحص السيرفر الملكية والنسخة والدرجة والفتح ويسجل التسليم والمكافآت ذريًا، مع idempotency key ومعالجة التعارض. لا تُعتمد localStorage أو route guards أو درجات يرسلها العميل كحماية.

## 7. الاختبارات والنشاط

- القبلي/البعدي: محاولات متعددة دون وقت، وأسئلة مختلفة بينهما مبدئيًا. المثال الأولي للقبلي 20 مفردة: 15 اختيارًا من متعدد و5 صح/خطأ بأوزان متساوية. «السؤال الأول/الثاني» في المادة الأصلية يعني **قسمين**، وليس سؤالين فقط. العدد والأنواع والأوزان قابلة لاعتماد الباحث؛ لا hardcoding لعدد 20 في المكونات.
- التعليمات تعرض الهدف والعدد الفعلي وأنواع الأسئلة، لا وقت محدد، تعدد المحاولات، اختيار بديل واحد، إمكانية الرجوع والمراجعة، عدم تعديل المحاولة المسلّمة، وسياسة الحفظ الفعلية. النشاط والذاتي يعرضان أيضًا شرط إتاحتهما ومعنى إكمالهما.
- سؤال واحد ظاهر مع رقم السؤال والنوع وعدد المجاب عنه والسابق/التالي. يمكن الانتقال دون إجابة والرجوع لاحقًا. تغيير الإجابة قبل التسليم مسموح ويحفظ عند التنقل.
- بعد آخر سؤال: مراجعة حالة كل الأسئلة وأزرار للانتقال، وبالأخص غير المجاب. سياسة العرض المؤقتة: لا تأكيد نهائي/تسليم قبل إجابة الكل. يذكر الشرط بوضوح ويظل التصحيح ممكنًا. تكرار تأكيد الطلب لا ينشئ محاولة ثانية.
- لا عرض لمفاتيح التصحيح أو الإجابات الصحيحة أثناء القبلي والبعدي، ولا في نتيجتهما حاليًا. النشاط والذاتي يقدمان تغذية راجعة تعليمية بعد الإرسال: الاختيار، الإجابة الصحيحة، سببها، ومصدر مناسب للمحتوى. مصدر التحرير الداخلي أوسع من المرجع المعروض للمتدرب.
- النشاط اختيار من متعدد للتدريب بلا شرط نجاح؛ إكمال جميع الإجابات وتسليمها يكفي. الذاتي من 100% وعتبته 50% شاملة الحد، ومحاولاته غير محدودة مبدئيًا. لا قبلي درس، ولا امتحان بين موديولين.
- نتيجة بعدي لا تعرض «ناجح/راسب» أو شهادة؛ لم تعتمد عتبته ولا سياسة المحاولة الداخلة في التحليل ولا التصحيح التفصيلي. حالات attempt في التخزين مستقلة عن حركات UI وحالة فشل الشبكة العابرة.

## 9. عقود البيانات وحد الخدمة

العقود في [`contracts.ts`](contracts.ts) تشترك منها أنواع التحرير مع التطبيق، وتبقى واجهة `TrainingService` فيه تصميمًا مستقبليًا غير منفذ. عقود التنفيذ المحلي وZod في `src/domain/models.ts`؛ لا تطابق مفترض بين مخطط الحالة المحلي وDTO الإنتاج. تشمل أنواع التصميم `EnvironmentConfig`, `Module`, `Lesson`, `Element`, `ContentBlock`, `Question`, `AssessmentDefinition`, `Attempt`, `Progress`, `Achievement`, `ContactInfo`، وأسباب الإجابات والمصادر والنسخ والاعتماد. تتضمن سجلات التسليم والإكمال المرجعية وحالات الوصول المشتقة.

- ID ثابت لكل موديول/درس/عنصر/كتلة/سؤال/خيار/تعريف/محاولة/إنجاز. `order` مستقل، ولا URLs مشتقة من الاسم العربي. الأعداد من البيانات، والعلاقات بالمعرفات.
- `EditorialMeta`: حالة `draft/approved`، نسخ المحتوى والتقويم عند انطباقهما، مصادر وتاريخ الوصول الفعلي وحالة التحقق والاعتماد. لا `approvedBy/approvedAt` إلا مع اعتماد فعلي؛ `approved` يتطلبهما.
- `Question` اتحاد `single-choice` و`true-false` مع وزن موجب ومفتاح تصحيح وتفسير في **نموذج التحرير فقط**. `DeliveredQuestion` منفصل خالٍ من المفتاح والتفسير والتحرير الداخلي؛ TypeScript لا ينقّي JSON تلقائيًا، لذا يلزم DTO serialization صريح لاحقًا.
- `AssessmentDefinition` يحدد النوع والموضع والنسخة والأنواع وسياسة المحاولات. الأسئلة محفوظة في نسخة immutable؛ قبل اعتمادها تبقى draft. تعريف صفري الأسئلة أو وزن غير صالح يمنع بدء محاولة.
- `Attempt` اتحاد draft/submitted يثبت الإجابات والدرجة عند التسليم. `AttemptView` يعرض النسبة والتغذية الراجعة المسموحة فقط؛ ليس مرجع التحرير.
- `Progress` حقائق تراكمية، و`ProgressSnapshot` حالات مشتقة؛ مجرد استعادة snapshot لا تمنح أهلية أو نقاطًا جديدة.

عند التنفيذ تُتحقق قيود البيانات عند حد الخدمة: معرفات فريدة وعلاقات صحيحة وترتيب معلوم ونسخ متطابقة، وأسئلة/أجزاء/قوائم مطلوبة غير فارغة. للاختيار الواحد بديلان على الأقل ومفتاح ضمن البدائل؛ للصح/الخطأ بديلان بالضبط. لكل سؤال إجابة واحدة ذات questionId معروف وoptionId تابع له؛ لا يكفي تطابق عدد الإجابات مع العدد الكلي إذا احتوت تكرارًا. مجموع الأوزان موجب، و`0 <= earned <= possible`، ومراجع التصحيح تشير إلى مصادر موجودة، والمصدر verified له تاريخ وصول فعلي. لا يمثل اتحاد TypeScript بديلًا عن هذه الفحوص في runtime.

### 9.1 الحد الصغير المقترح

`TrainingService` واجهة Promise واحدة: `getEnvironment` و`getCatalog` للبيانات العامة؛ `getModule/getLesson/getElement` للمحتوى المتاح؛ `getAssessmentInstructions`؛ `getProgress`؛ `startAttempt/getAttempt/saveAnswers/submitAttempt`؛ `markElementStarted/acknowledgeElement`. الأمر الأول للعنصر يسجل بدء التفاعل وبدء الدرس/الموديول التابعين بعد فحص الفتح، دون إكمال أو نقاط؛ الثاني يسجل الإقرار في نهاية الأجزاء. بيانات المستخدم/الجلسة تؤخذ من سياق adapter، لا من `learnerId` حر يختاره استدعاء UI.

هذه واجهة التصميم المستقبلية. في الثالثة تعتمد المكونات حد `TrainingPort` الصغير (`execute/getSnapshot/subscribe/getAttemptView/reload` وcatalog منقح)، ويربطه `TrainingProvider` بـ`DemoAdapter`. لا وصول من صفحات المتدرب إلى localStorage أو مفاتيح التصحيح. القواعد في `src/domain/training.ts` مستقلة عن React؛ استبدال النقل بـHTTP لاحقًا يتطلب تنفيذ الحد وربط DTO السيرفر، ولم يُنفذ الآن. تصميم HTTP المستقبلي يطلب رموز الأخطاء الثابتة: unauthenticated، forbidden، not-found، locked، invalid-data، invalid-transition، conflict، storage-unavailable، network. الحد المحلي الحالي يعيد Result برسالة عربية، مع fault للتخزين/الفساد/التعارض في snapshot. لا إرجاع لنتيجة نجاح عند فشل الحفظ.

حدود adapter العرض **منفذة في الثالثة**: بيانات محتوى ثابتة ومحاكاة جلسة وحفظ نفس المتصفح. ينقّي adapter كائنات الأسئلة المعروضة بإعادة بنائها دون المفاتيح، ولا يعيد تغذية القبلي/البعدي. مفاتيح التصحيح في mock مكشوفة تقنيًا ضمن الحزمة لأغراض العرض حتى لو أخفتها الواجهة، فلا يصلح لجمع بيانات دراسة محمية. في الإنتاج لا تُرسل المفاتيح أو الأسباب قبل السماح بالتغذية الراجعة؛ يقيم السيرفر ويعيد DTO منقحًا، وللقبلي/البعدي يبقى التصحيح محجوبًا حسب السياسة المعتمدة. لا تقبل الدرجة أو الأهلية أو مكافأة من العميل.

مفاتيح idempotency لأوامر التسليم/إقرار العنصر، وقيد فريد للمكافأة بحسب `(learner, eventType, subjectId, contentVersion)`، يحميان من تكرار الضغط أو refresh؛ لا تمنح كل محاولة حدث إكمال جديدًا. `saveAnswers` بتوقع revision يمنع الكتابة الصامتة فوق تعديل أحدث. لا endpoint API أو قاعدة بيانات ضمن هذه المرحلة.

## 22. استعراض الموديولات والتسليم الجزئي والصفحات القصيرة

المستخدم يريد فهرس المحتوى دون تمرير،معglow وانتقال خلفية بلون خفيف. الكارت ورابطه يفتحان مقدمة الموديول؛يمكن للزائر والمتدرب استعراض المقدمة والأهداف وعدد وأسماء الدروس قبل التأهل،بما في ذلك الموديولات التالية. عند محاولة فتح درس،تظهر شروطه والخطوة المتاحة. استعراضmetadata لا يسجل إقرار قراءة أو محاولة أو نقاطًا،ولا يغير أهلية التدريب. حراسةlesson/element/part/assessment والأوامر تبقى قائمة؛فتح معلومات الموديول لا يفتح التدريب.

تعريفات التقويم تسجلminimumAnsweredQuestions وsubmitRequiresAllAnswers. سياسة الحد الأساسية فيdemoPolicy،والمحاكاة المصغرة للاختبار تحافظ على حد سؤالين لأسئلتها الثنائية. لم تتغير الأسئلة أو مفاتيحها أو ترتيبها أو مصادرها؛بقيتcontentVersion0.4.1-draft لتستمر استعادة التقدم السابق المتوافق. بقي عدم استعادة0.4.0/0.3 دون حذف صامت.

## 27. أربعة موديولات بلون الهيدر وفهرس مضغوط

طلب المستخدم تغيير رقمَي الموديولين المنقولين إلى1و2،وإضافة موديولين من تأليفنا. رقم العرض وحده يتغير؛المعرفات والروابط والنصوص المرجعية ومحاولات التقويم والتقدم تبقى ثابتة. لا يفسر الرقم الجديد بأنه تغيير لأسئلة محاولة محفوظة. ملف authored-content.json مستقل بحالةdraft ومراجعه،وcatalog يجمعه مع المصدر دون تعديل الملف المرجعي أو مفتاح/نسخة التخزين.

الموديول3للتصميم التعليمي: تحليل المتعلمين والأهداف،وبناء السيناريو،وتصميم التفاعل والتغذية الراجعة. الموديول4للجودة والإتاحة: وضوح الوسائط والإتاحة،واختبار الاستخدام والتوافق،والتحسين المبني على أدلة. ثلاثة دروس لكل موديول،ولكل درس أهداف وثلاثة أقسام محتوى ونشاط نصي بمطلوب ومعايير وإرشادات ومراجع. لم يُخترع فيديو أو اعتماد علمي أو درجة آلية للأنشطة،ولا تُعد إضافة الموديولين اعتمادًا للمحتوى أو تمديدًا تلقائيًا لبنكي القبلي/البعدي.

لون البطاقات والعناوين والقائمة والدعم مطابق لأزرقnavbar #145da0،بخلفيات بيضاء وتظليل أزرق خفيف. فهرس بأربع بطاقات2×2 ومعلومات المجموعة والمسار داخل نافذة يفتحها زر واضح،بدل إطالة الصفحة. يُضغط تكرار العناوين والمسافات في الدروس،وتعرض الأهداف بعمودين والنشاط بجانب حقل الإجابة على المساحات الواسعة؛الهاتف بعمود واحد للقراءة.

لا سابق/تالي خارج الاختبارات مهما تغير المقاس؛التنقل بعناوين مباشرة. أكد المستخدم في هذه الجولة: «أفضّل التمرير الطبيعي عند الضرورة لعرض النص كاملًا». لذلك يُستهدف فهرس دون تمرير على المقاسات المفحوصة،مع السماح الطبيعي في قراءة المحتوى الطويل أو المقاسات الأضيق والتكبير،دون قص أو تصغير غير مقروء أو إخفاء overflow للصفحة. أدلة جديدة مستقلة في review/four-blue-modules.

## 28. أهداف الدرس عند الضغط على عنوانه

الضغط على اسم درس في القائمة الجانبية لأي موديول يحدد الدرس ويفتح أقسامه، وينتقل مباشرة إلى مسار أهدافه. اختيار درس آخر يغلق أقسام السابق ويفتح المختار؛ تكرار اختيار الدرس الحالي يعيده إلى أهدافه ويبقي أقسامه مفتوحة. إذا كانت الأهداف نفسها نشطة فلا تضاف زيارة مكررة إلى سجل الرجوع. على الهاتف تغلق نافذة قائمة الدروس بعد الاختيار لتظهر الأهداف. يبقى اختيار المحتوى والنشاط بروابطهما المباشرة متاحًا، وتظل حراسة الدخول والتأهل والتخزين كما هي.

## 29. امتداد عمود الدروس إلى التذييل

يمتد عمود قائمة الدروس في صفحات الموديولات وأقسام الدروس على الكمبيوتر من نهاية الهيدر إلى بداية التذييل، بصرف النظر عن عدد الدروس. تتوزع المساحة الفعلية عبر تخطيط الصفحة دون طرح ارتفاع ثابت للهيدر أو التذييل. عند طول المحتوى ينمو العمود معه ويظل التمرير الطبيعي متاحًا. على الهاتف تبقى نافذة قائمة الدروس واختيار أهداف الدرس كما هما، دون فرض عمود جانبي دائم.

## 30. تقليل التمرير عبر صفحات البيئة

تحسين عام لارتفاع الصفحات، يشمل المسافات في الهيدر والتذييل والعناوين والدليل والرئيسية والأهداف والاتصال وتعليمات التقويم، وليس صفحة المثال وحدها. تصغير معتدل للعناوين ومسافات السطور مع بقاء نص قراءة الدروس14pxوحقول إدخال الهاتف16px. يُستفاد من العرض بتوزيع المشرفين بثلاثة أعمدة، والنشاط والإجابة والدعم في شبكة تتدفق طبيعيًا على الهاتف.

الفيديو بنسبة16:9وبحجم يتبع الارتفاع والعرض المتاحين، مع بقاء تكبير YouTube. الصور كاملة دون قص وبحجم معاينة مناسب، وزر التكبير في رأس البطاقة بجانب عنوانها بدل تكرار العنوان أسفلها. تُختصر مسافات قائمة الدروس وتكرار ترقيمها المرئي فقط؛ عنوانها الكامل متاح لقارئ الشاشة، وتبقى ممتدة إلى التذييل. يظل الدعم الثابت ظاهرًا والمرن عند الطلب، وجميع الإرشادات قابلة للقراءة.

لا تقسيم تلقائي أو سابق/تالي خارج التقويمات، ولا تثبيت ارتفاع الصفحة أو حجب تمريرها أو قص النص لتحقيق أرقام الفحص. يُقلل التمرير قدر الإمكان على المقاسات المفحوصة، وتظل القراءة الطبيعية متاحة للنصوص الطويلة والشاشات القصيرة والتكبير كما وافق المستخدم. لا تغيير للمحتوى أو معرفاته أو قواعد الاختبارات أو الحفظ.

## 31. مسافات متساوية وإطار محتوى مستدير

تضم منطقة المحتوى كلها، بما فيها قائمة الدروس، داخل إطار مشترك بزوايا مستديرة وحد أزرق خفيف. المسافة من الإطار إلى نهاية navbar ومنه إلى بداية footer وإلى طرفَي الشاشة تستخدم القيمة نفسها: clamp(8px,1vw,16px). الزوايا18pxعلى الكمبيوتر و14pxعلى الهاتف. يمتد الإطار داخل المساحة المتبقية في الصفحة، وينمو مع النص الطويل دون قص أو حجب التمرير. يبقى عرض الرئيسية والأهداف متوازنًا داخل الإطار، وقائمة الهاتف نافذة.

هذا يحدّث امتداد عمود الدروس: حداه الآن داخل الإطار بدل ملامسة الهيدر والتذييل مباشرة، مع مسافة خارجية متساوية حوله. قواعد التنقل وفتح الأهداف والتقويمات والحفظ لا تتغير.
