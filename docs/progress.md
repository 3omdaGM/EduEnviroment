# التقدم

التاريخ: 2026-10-16 · المرحلة **1/6**: تثبيت الهيكل والقواعد — مكتملة توثيقيًا.

## ما أُنجز

- فحص المجلد وGit والملفات المخفية والمرفقات؛ لم يوجد سوى `.gitignore` ونص الطلب المرفق، ولا تطبيق أو حزم أو lockfile أو وثائق أو شعارات وأسماء إضافية.
- كتابة مصدر حقيقة واحد للصفحات والقالب والهوية وRTL والـresponsive وخريطة routes، وحالات الأهلية والمحاولات والتقدم وصلاحيات الوصول وأسباب القفل.
- توثيق الحدود الدقيقة للقبلي والذاتي واستدامة النجاح والمكافآت، والسياسات البحثية غير المحسومة، وحد الفصل بين demo وHTTP والإنتاج.
- وضع عقود TypeScript أولية ومعها config مؤقت معلن `first-submitted-pre`، بلا تنفيذ domain أو adapter أو auth أو Backend أو واجهة.

## الملفات المؤثرة وكيفية المراجعة

- `docs/project-spec.md`: المواصفة التفصيلية ومصفوفة تتبع الطلب ومعايير التحقق المستقبلية.
- `docs/contracts.ts`: نماذج البيانات وعقد الخدمة/config العرض؛ ليس تطبيقًا قابلًا للتشغيل.
- `docs/decisions.md`: المؤكد والمقترح والقرارات البحثية المعلقة.
- `docs/progress.md`: هذا السجل ونتائج التحقق والخطوة التالية.
- `AGENTS.md`: تعليمات مختصرة لحماية القواعد والنطاق. لم يعدل `.gitignore` أو ينشأ package manifest.

للمراجعة افتح `docs/project-spec.md` في قارئ Markdown ثم العقود والقرارات. لا يوجد أمر `npm run dev` أو build أو خادم في هذه المرحلة؛ لم تُركب تبعيات تطبيق. ملفات TypeScript ليست إعداد مشروع frontend.

## التحقق المنفذ فعليًا

- نجح تدقيق الملفات الخمسة: UTF-8، نهاية الأسطر والمسافات، الروابط المحلية في Markdown، وجود النماذج والمسارات المطلوبة، ترتيب الموديولات، الاسم الكامل، ومصفوفة أحجام العرض المستقبلية. تدقيق تغطية نصي مع مراجعة للمواصفة، لا اختبار لسلوك تطبيق.
- طابقت الأمثلة الحدية السبعة في جدول الدرجات المقارنات الصحيحة `2 * earned <= possible` و`2 * earned >= possible` باستخدام Python. هذا تحقق حسابي من أمثلة المواصفة، وليس اختبارًا لمحرك تقويم منفذ.
- نجح فحص صياغة العقود بـ`node --check docs/contracts.ts` على Node `24.19.0`.
- نجح فحص أنواع العقود بـTypeScript `7.0.2` مع `--noEmit --strict --exactOptionalPropertyTypes --noUncheckedIndexedAccess --target ES2022 --module ESNext --moduleResolution Bundler`. جُلبت أداة التحقق فقط إلى cache مؤقت في `/workspace/work`؛ لم ينشأ `package.json` أو lockfile أو `node_modules` في المشروع. فشل الاتصال الأول من sandbox، ثم نجح عبر إذن الشبكة المحدود للأداة.
- لم يرصد فحص whitespace عبر `git diff --no-index --check` مشكلات في الملفات الجديدة؛ تأكد بقاء `.gitignore` دون تغيير. لا يوجد كود سابق تغير.
- لم تُنفذ اختبارات متصفح أو responsive أو إتاحة بصرية أو frontend/Backend؛ لا واجهة تعمل في هذه المرحلة. معاييرها في §12 من المواصفة للمرحلة التي يوجد فيها تنفيذ.

لإعادة فحص الأنواع عند توفر أداة TypeScript، من جذر المشروع:

```sh
tsc --noEmit --strict --exactOptionalPropertyTypes --noUncheckedIndexedAccess --target ES2022 --module ESNext --moduleResolution Bundler docs/contracts.ts
```

## التالي عند طلب المرحلة الثانية

- تثبيت أساس frontend باستخدام إصدارات مستقرة متوافقة موثقة وlockfile وTypeScript strict، دون Backend أو DB.
- بدء قالب الهوية المشترك والـRTL والتنقل وخريطة المسارات وحالات 404/القفل/الفراغ/الخطأ، بهيكل محتوى منفصل عن العرض والقواعد؛ يحدد طلب المرحلة الثانية مدى التنفيذ التفصيلي.
- تجهيز بيانات عرض مؤقتة واضحة وبدائل الأسماء والشعارات ومراجعة التباين والإتاحة وresponsive قبل توسيع التجربة.
- استخدام حدود الخدمة المخططة وعدم تحويل السياسات المعلقة إلى اعتماد ضمني، ثم تنفيذ الاختبارات ذات المعنى حسب الجزء المبني.

لم تبدأ المرحلة الثانية. الأسماء والشعارات والمحتوى المعتمد وسياسات التحليل والبعدي والشهادة ما زالت معلقة لدى الباحث ولا تمنع إتمام مواصفة المرحلة الأولى.
